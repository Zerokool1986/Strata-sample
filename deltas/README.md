# Deltas, The Change Log of the Store

This folder holds **delta records**: one file per change to the
knowledge store. A delta names exactly which facts were added,
modified, or removed, so a reviewer can see a change to knowledge the
way a diff shows a change to code.

File a delta (`templates/delta-record.md`, named `DLT-SHORT-SLUG.md`)
whenever a supersession, a disproof, or a contradiction resolution
changes the store, whenever knowledge moves (from a repo store into
the home store, for example), and whenever a consolidation proposal
that changes a summary or `CORE.md` is applied. Link the delta from
the entries it touches, in their `evidence:`.

A delta is a log, not a category of knowledge. It records what
happened; it does not hold a claim. That is the same standing as the
episodic session records: a log area, not a claim category, and the
same rule applies, a delta is never edited after it is filed. If a
delta turns out to be wrong, file a correction note beside it, the way
a wrong session record gets a correction note, never a quiet repair.

Trivial changes (a typo fix, a date bump on re-verification) do not
get a delta: one line in the pass record covers them.
